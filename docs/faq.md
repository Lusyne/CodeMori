# 常见问题

## 需要一直打开独立客户端吗？

不需要。插件携带原生核心，在操作时调用；无需单独启动 CodeMori 桌面程序或后台服务。

## VS Code 和 JetBrains 的资料能共用吗？

同一台电脑默认都使用用户主目录下的 `.codemori/`。不同电脑之间不会自动同步个人库；可使用个人 JSON 备份迁移，或将适合团队的内容明确保存为项目共享。

## 飞书、Notion、Obsidian 都能直接唤起客户端吗？

目前符合支持范围的飞书文档显示“在飞书中打开”，同时保留浏览器入口。Obsidian `open` 链接由系统打开对应应用。Notion HTTP(S) 链接使用浏览器，是否转交客户端由系统/浏览器决定，CodeMori 不保证直接唤起 Notion。详见[飞书说明](feishu-opening.md)。

## 为什么搜索不到文档正文？

知识搜索覆盖保存的标题、摘要、标签、片段，以及手动索引的受支持源码注释。远程正文和本地 Markdown 正文不自动进入搜索。可在摘要里留下重要关键词；AI Skill 还能检索当前本地源码。

## 文档里的代码链接点不开怎么办？

先安装对应 IDE 和 CodeMori，并打开目标项目。确认团队已提交 `.codemori/project.json`。文档平台可能拦截自定义协议，可以复制链接，在 IDE 中使用“打开代码位置链接”粘贴。跨克隆定位和锚点限制见[代码链接](code-links.md)。

## 只是格式化，为什么也提示待复核？

提示依据已保存代码的指纹变化。格式变化有时也影响含义，系统不替用户判断。检查后可使用当前文件的“一键确认待复核”；若包含模块项，它会确认整个目录的基线。显示后代码再次变化时需要刷新再检查。

## 代码旁提示可以隐藏吗？

可以，VS Code 设置或两端的对应菜单可切换文档提示。隐藏只影响展示，不删除关联，面板仍可查看资料。见[提示设置](contextual-knowledge.md)。

## 团队成员为什么看不到我保存的资料？

新建默认保存到个人库。团队资料需要选择“项目共享（随 Git）”，提交项目 `.codemori/shared.json` 和 `.codemori/.gitignore`，同事再拉取。仓库里的 Markdown 正文也要单独提交。飞书、Notion 的访问权限仍由原平台控制。

## 署名能证明是谁操作的吗？

署名是用户设置的显示名和本机标识，用于区分创建者、修改者。它不是登录认证、权限控制或不可伪造的审计签名；同名与换机情况需结合团队流程判断。

## 保存时出现版本冲突怎么办？

先保留自己的编辑内容，再刷新并重新打开记录。比较最新内容后重新保存。共享 JSON 出现 Git 冲突时，先通过正常 Git 流程解决；不要直接覆盖来跳过检查。

## Skill 会把说明自动发到飞书吗？

不会。它向当前 AI 助手提供资料和源码证据，助手按你的请求生成聊天内容或本地草稿。发布、保存共享资料和复核是独立操作。使用外部 AI 服务时，送给该助手的上下文受该服务及你自己的设置约束。

## 在哪里反馈问题？

仓库公开后在 GitHub Issues 反馈；记录插件版本、IDE 版本、OS/CPU、复现步骤和脱敏错误。不要附上完整个人数据库或私人文档链接。
