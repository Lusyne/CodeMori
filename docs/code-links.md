# 从文档回到代码

在源码文件中执行 **CodeMori: 复制代码位置链接**，选择 IDE 链接或 Markdown 双入口，再贴到设计说明、问题记录或笔记里。链接指向项目中的文件及保存时行号，不包含本机绝对路径，也不会上传代码。

## 团队使用

1. 安装 CodeMori，在本地项目打开源码，将光标放在需要的位置，再复制链接。
2. 首次复制会创建项目 `.codemori/project.json`。将它与 `.codemori/.gitignore` 提交到 Git，后续保留这个项目标识；无需为了创建代码链接先保存共享片段。
3. 同事拉取该文件，在自己的 IDE 打开项目，再点击文档里的对应 IDE 入口。插件按项目标识和相对路径定位到同事自己的克隆。
4. 文档应用不允许这类链接时，复制完整链接，在 IDE 执行 **CodeMori: 打开代码位置链接** 并粘贴；两端都能识别 CodeMori 的 VS Code 与 JetBrains 链接。

## 接收链接时

- 当前窗口有匹配的本地项目时打开相对文件。同一项目有多个打开的克隆时，由用户选择。
- VS Code 当前窗口没有匹配项目时，可选取包含 `project.json` 的本地克隆目录，核对标识后打开文件。
- JetBrains 在已打开的工程中匹配；没有匹配工程时提示先打开正确工程，再用粘贴链接入口。不会自动克隆仓库或导入陌生项目。
- 项目标识不匹配、文件缺失、路径越界、符号链接或非法参数会被拒绝。文件重命名后，需要重新生成链接并更新文档。

0.4新链接包含内容/符号锚点，可在插入行和部分移动场景中重新定位；无法唯一匹配时提示修复。旧链接仍按原路径/行号处理，不跟踪分支或提交版本。详见[耐用链接范围](contextual-knowledge.md)。文档平台、浏览器、操作系统和 IDE 自身可能要求确认是否打开外部应用，也可能拦截自定义协议；安装插件不能改变这些平台规则。只有目标 IDE 的系统协议已注册时，点击链接才能交给它。

## 项目文件与隐私

`project.json` 只有格式版本和随机项目 ID；链接还携带相对文件路径和行号。路径使用编码以保留中文、空格与 `+/#/%` 等字符，编码不是加密。分享给项目成员时，他们仍需要自己的本地源码。不要重新生成已有项目标识，否则旧链接会失效；独立派生的新项目若希望与原项目区分，应在团队确认后建立自己的标识并重新生成链接。
